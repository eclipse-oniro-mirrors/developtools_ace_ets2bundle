### 原始描述

当前 ArkTS 动态编译为非严格类型校验，允许开发者显式传递 `undefined` 值到 `@Require` 修饰的 non-null 类型字段。该需求要求编译器识别该场景并输出告警，提示开发者修正代码。

**问题场景：**
```typescript
@Component
struct Parent {
  build() {
    Column() {
      Child({ requiredNum: undefined })  // ← 应告警
    }
  }
}

@Component
struct Child {
  @Require requiredNum: number;  // non-null 类型

  build() {
    Column() {
      Text(`number: ${this.requiredNum}`)
    }
  }
}
```

### 背景与痛点

| 用户类型 | 当前痛点 | 影响 |
|----------|----------|------|
| ArkUI 应用开发者 | 传递 `undefined` 到 non-null 类型的 `@Require` 字段时，编译器无提示，可能导致运行时异常 | 潜在的运行时错误难以早期发现 |
| 编译器工具链开发者 | 缺少对 `@Require` 字段类型一致性的静态检查能力 | 无法在编译阶段提前预警类型不匹配 |

### 初始范围

**包含：**

1. `@Require` 修饰的字段类型校验
2. non-null 类型字段（不含 `undefined` 的类型）检查
3. 显式传递 `undefined` 值的场景检测
4. 顶层字段检查（不递归嵌套对象）
5. 编译器 WARNING 级别告警

**不包含：**

1. 其它修饰符（`@Prop`、`@State` 等）的类似检查
2. 可选类型字段传递 `undefined`（如 `number | undefined`）
3. 非 `@Require` 字段的类型校验
4. 嵌套对象属性内部的 `undefined` 检查
5. 运行时组件行为的修改
6. 新增 API 或公共接口

### 初始假设

| 假设 | 类型 | 验证方式 | 状态 |
|------|------|----------|------|
| `@Require` 是编译时标记，不生成运行时代码 | 技术 | 需求澄清 | 已确认 |
| 告警级别为 WARNING 而非 ERROR | 需求 | 需求澄清 | 已确认 |
| non-null 类型包含基本类型、非空联合类型、对象类型 | 需求 | 需求澄清 | 已确认 |
| 仅检查显式传递 `undefined` 的场景 | 需求 | 需求澄清 | 已确认 |

5. 输出 WARNING 级别告警信息
